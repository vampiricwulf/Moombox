### Task 1: Folder-open force-quoting on Windows

Ruling **W R-3** (spec §0): "Apply the browser-launch command-line quoting to both folder-open paths (the dashboard route and the TUI `O F` chord) in the shared helper, so a Windows directory whose path contains `=` opens."

**Where it is today.** `OpenPathCommand(target)` → `openPathCommandFor(runtime.GOOS, target)` in `internal/web/server.go` builds `exec.Command(program, target)` and nothing else. Go's `os/exec` quotes an argument only when it contains a space, a tab or a quote, so a directory named `C:\Moombox\output\Stream=Archive` reaches `explorer.exe` bare, and explorer's legacy parser splits the unquoted `=` into separate arguments and opens nothing. The TUI's browser launch already proves the fix: `openBrowserCmd` (`internal/tui/openbrowser_windows.go`) sets `SysProcAttr.CmdLine` to `explorer.exe "<url>"` with embedded `"` stripped, and its comment records that the failure was verified empirically on every YouTube `watch?v=` URL.

**Why this needs a build-tagged file.** `server.go` is not a `_windows.go` file and `syscall.SysProcAttr` carries a `CmdLine` field **only** on Windows — writing it in `server.go` would not compile on Linux, and `GOOS=linux go vet ./...` is a merge gate. So the quoting lives in a tiny build-tagged pair and the shared helper calls it. `openPathCommandFor` keeps its injected `goos`, so `TestOpenPathCommandIsTheSameOnBothHosts` still asserts both platforms' argv from either host and stays exactly as meaningful as it is today.

**Callers need no change, and that is already pinned.** `POST /api/jobs/{id}/open-folder` (`internal/web/routes/jobs.go`) and the TUI `O F` chord (`cmd/moombox/tui_wiring.go`) both go through `web.OpenPathCommand` + `web.StartDetached`, and two structural tests already say so: `TestOpenFolderRouteUsesTheSharedCommand` (`internal/web/routes/jobs_test.go`) and `TestOpenFolderChordUsesTheSharedDetachedSpawn` (`cmd/moombox/tui_wiring_openfolder_test.go`). **No new pin is needed** — Step 6 runs both to prove the fix reached both callers for free.

```go
package web

import "testing"

// TestWindowsOpenPathForceQuotesTheTarget is W R-3's pin.
//
// Go's os/exec quotes an argument only when it contains a space, a tab or a
// quote, so a directory path like C:\Moombox\output\Stream=Archive reaches
// explorer.exe bare — and explorer's legacy parser splits an unquoted '='
// into separate arguments and silently opens nothing. The TUI's browser
// launch (openBrowserCmd, internal/tui/openbrowser_windows.go) has carried
// the force-quoted CmdLine for exactly this reason since it was verified
// empirically on watch?v= URLs; the folder-open path never got it.
//
// Windows-only by necessity: syscall.SysProcAttr has a CmdLine field on no
// other platform. TestOpenPathWindowsArmForceQuotes in server_test.go is the
// half a Linux runner can see.
//
// MUTANTS, one per assertion:
//   - delete the forceQuoteCmdLine call in openPathCommandFor (back to a bare
//     exec.Command) -> SysProcAttr is nil and the first assertion fails;
//   - write the quotes into the argv instead (exec.Command(program, `"`+
//     target+`"`)) -> the CmdLine assertion fails AND the Args assertion
//     fails, because explorer would then be handed a literally-quoted path;
//   - drop the embedded-quote strip -> the quoted-path row fails;
//   - drop the `if goos == "windows"` guard so every platform is quoted ->
//     the last rows fail, because xdg-open and open take their argv.
func TestWindowsOpenPathForceQuotesTheTarget(t *testing.T) {
	t.Run("a path with = and no spaces", func(t *testing.T) {
		const target = `C:\Moombox\output\Stream=Archive`
		cmd := openPathCommandFor("windows", target)
		if cmd.SysProcAttr == nil {
			t.Fatal("the Windows command carries no SysProcAttr — Go leaves an unquoted '=' for " +
				"explorer's legacy parser to split, and the folder never opens")
		}
		if got, want := cmd.SysProcAttr.CmdLine, `explorer.exe "`+target+`"`; got != want {
			t.Errorf("CmdLine = %q, want %q", got, want)
		}
		if len(cmd.Args) != 2 || cmd.Args[0] != "explorer.exe" || cmd.Args[1] != target {
			t.Errorf("Args = %v, want [explorer.exe %s] — the argv must stay exactly what it was; "+
				"Windows ignores it once CmdLine is set, and TestOpenPathCommandIsTheSameOnBothHosts "+
				"asserts it is byte-identical on every platform", cmd.Args, target)
		}
	})

	t.Run("an embedded quote cannot escape the quoting", func(t *testing.T) {
		// A Windows path cannot legally contain '"', so this is defensive
		// only — the same defence openBrowserCmd applies to URLs.
		cmd := openPathCommandFor("windows", `C:\out\a"b`)
		if cmd.SysProcAttr == nil {
			t.Fatal("no SysProcAttr on the Windows arm")
		}
		if got, want := cmd.SysProcAttr.CmdLine, `explorer.exe "C:\out\ab"`; got != want {
			t.Errorf("CmdLine = %q, want %q", got, want)
		}
	})

	for _, goos := range []string{"linux", "darwin", "freebsd"} {
		t.Run(goos+" is not quoted", func(t *testing.T) {
			cmd := openPathCommandFor(goos, "/home/u/Stream=Archive")
			if cmd.SysProcAttr != nil {
				t.Errorf("%s carries SysProcAttr %+v — only Windows needs the command line "+
					"rewritten; everywhere else exec passes argv straight through",
					goos, cmd.SysProcAttr)
			}
		})
	}
}
```

Create `internal/web/openpath_windows.go`:

```go
//go:build windows

package web

import (
	"os/exec"
	"strings"
	"syscall"
)

// forceQuoteCmdLine replaces the command line Go would build for cmd with an
// explicitly quoted one: `explorer.exe "<target>"`.
//
// Go's os/exec quotes an argument only when it contains a space, a tab or a
// quote. A directory path like C:\Moombox\output\Stream=Archive therefore
// reaches explorer.exe bare, and explorer's legacy parser splits an unquoted
// '=' into separate arguments and silently opens nothing — no error, no
// window, a button that appears to do nothing (W R-3). The TUI's browser
// launch has carried this same quoting since the behaviour was verified
// empirically on YouTube watch?v= URLs; the folder-open path never got it.
//
// THE DUPLICATION WITH openBrowserCmd (internal/tui/openbrowser_windows.go)
// IS FORCED, NOT ACCIDENTAL. internal/tui may not import internal/web (the
// import fence), and SysProcAttr.CmdLine exists only in the Windows syscall
// package, so neither copy can be hoisted into a shared untagged file.
// Change one and change the other.
//
// cmd.Args is deliberately left alone. Windows ignores argv entirely once
// CmdLine is set (syscall.StartProcess prefers sys.CmdLine over
// makeCmdLine(argv)), and TestOpenPathCommandIsTheSameOnBothHosts asserts the
// argv is byte-identical on every platform — that pin is what lets a Linux
// runner check the Windows spawn at all, so it must not be weakened here.
//
// The quote strip is defensive: a Windows path cannot legally contain a '"',
// but stripping it means no target can ever escape the quoting.
func forceQuoteCmdLine(cmd *exec.Cmd, program, target string) {
	cmd.SysProcAttr = &syscall.SysProcAttr{
		CmdLine: program + ` "` + strings.ReplaceAll(target, `"`, "") + `"`,
	}
}
```

func openPathCommandFor(goos, target string) *exec.Cmd {
	program := "xdg-open"
	switch goos {
	case "windows":
		program = "explorer.exe"
	case "darwin":
		program = "open"
	}
	cmd := exec.Command(program, target)
	// Windows only: Go leaves an unquoted '=' for explorer's legacy parser to
	// split, so a directory path containing one opens nothing (W R-3). The
	// argv above is unchanged — Windows ignores it once CmdLine is set.
	if goos == "windows" {
		forceQuoteCmdLine(cmd, program, target)
	}
	return cmd

### Task 3: The `internal/worker` race-test flake — diagnose, then fix

Spec §0 "follow-ups taken" and §5: **"The worker flake is diagnosed before it is fixed; a test-only wait is the fallback, not the first move."**

**What was observed.** `TestExecuteTwitchRegistersTheLiveChatDownloaderForItsWholeRun` (`internal/worker/twitch_chat_registry_test.go`) runs a real `twitch.ChatDownloader` on a pre-cancelled context. Once, under `-race` on Windows, `t.TempDir`'s cleanup reported **"The directory is not empty"**; two package re-runs and five targeted re-runs were green. The root cause was never nailed down in code.

**What the plan-evaluation run already established — treat this as the expected outcome of Step 2, and confirm it rather than rediscover it.** An instrumented run of exactly the probe below, on this host under `-race`, reproduced the phenomenon on **20 of 20** iterations and traced it to a production ordering bug in `internal/worker/orchestrator_twitch.go`:

```
ExecuteTwitch returned: context canceled (is context.Canceled: true)
  immediately after return, chat dir holds: chat.json.resume.json.tmp
  200ms later:                              chat.json.resume.json
```

`ExecuteTwitch`'s shutdown/user-cancel arm — locate it by `if !outageFinalize || parentCtx.Err() != nil || userCancelled.Load() {` — calls `twitchChatDl.Stop()` and then `return ctx.Err()`. It never reaches `resolveChatOutcome`, which is the ONLY place that waits on `chatDone`. So the chat goroutine's deferred teardown (`flush()` → `saveResumeState()` → `utils.ResumeStore.Save`) is still mid-write when the orchestrator has returned: the `.tmp` is on disk, the `ReplaceFile` has not happened yet, and the caller — in production, the worker; in the test, `t.TempDir`'s cleanup — is already tearing the directory down.

A control probe in `internal/twitch` (call `cd.Start(pre-cancelled ctx)` directly, then list and remove the directory) showed **`Start` itself is clean**: 10 of 10 iterations left only the finished `chat.json.resume.json`, with `RemoveAll` settling in 0–0.7 ms.

**This is a production bug, not a test artefact,** which is why the plan's earlier branch set was wrong and why the fix is branch (d) below. A cancelled or shut-down Twitch job has its chat goroutine writing into staging *after* the orchestrator has declared the job finished — and `/retry` (`ReinitializeJob`) deletes that staging. // chatShutdownGrace is how long any cancel/shutdown path gives a chat
// goroutine to finish after it has been Stop()'d. It is the same grace
// resolveChatOutcome already applies after its own Stop(), named here so the
// three sites that need it cannot drift to three different numbers.
const chatShutdownGrace = 2 * time.Second

// waitForChatShutdown waits up to grace for a chat goroutine's done channel to
// close, and reports whether it did. A nil channel means no goroutine was
// started, which is trivially "finished".
//
// BOUNDED, never a bare receive: a downloader wedged in a socket read must not
// hold a shutdown open. The caller Stop()s first — this waits for the teardown
// that Stop triggers (flush, then the resume-sidecar write), not for the
// session itself.

// directory. An exit that returns without it leaves ResumeStore.Save mid-
// rename in a directory the caller may already be deleting — /retry's
// ReinitializeJob does exactly that.
func waitForChatShutdown(done chan struct{}, grace time.Duration) bool {
	if done == nil {
		return true
	}
	timer := time.NewTimer(grace)
	defer timer.Stop()
	select {
	case <-done:
		return true
	case <-timer.C:
		return false
	}
}

// removeWithRetry removes dir, retrying until it succeeds or bound elapses.
//
// Windows deletes a file another process has opened WITH share-delete by
// marking it DELETE-PENDING: the DeleteFile call succeeds, the name stays in
// the directory until the last handle closes, and the RemoveDirectory that
// follows fails with ERROR_DIR_NOT_EMPTY — "The directory is not empty".
// testing's own TempDir cleanup retries only the Windows *sharing violation*
// and *access denied* classes, not that one, so a scanner holding a
// freshly-written file for a moment aborts the whole package run.
//
// This is the FALLBACK, and it is legitimate only once the probe has shown
// that nothing of ours is still writing: ExecuteTwitch waits for the chat
// goroutine on every exit, Start's teardown finishes before Start returns,
// and ResumeStore.Save closes its handle before ReplaceFile. The handle is
// somebody else's, and the only thing the test can do about it is outlast it.
func removeWithRetry(dir string, bound time.Duration) error {
	deadline := time.Now().Add(bound)
	for {
		err := os.RemoveAll(dir)
		if err == nil {
			return nil
		}
		if time.Now().After(deadline) {
			return err
		}
		time.Sleep(20 * time.Millisecond)
	}
}

// waitForDirRelease makes the test, not testing.TempDir, own the removal of
// dir. Registered AFTER t.TempDir returned it, so it runs BEFORE TempDir's own
// cleanup (t.Cleanup is LIFO): by then the directory is gone and TempDir's
// RemoveAll is a no-op on a missing path.
//
// One-way: on a run where nothing holds a handle the first RemoveAll succeeds
// and this costs nothing, so it can turn a passing run into a failing one only
// by reporting a handle genuinely held for five seconds — which would be a
// real bug and should fail.
func waitForDirRelease(t *testing.T, dir string) {

### Task 4: A render cache for the TUI status bar

Spec §0 "follow-ups taken" and §3: `StatusBarModel.View()` re-renders every frame and `tallyJobs` walks the whole job list each time — **70 of a no-change frame's 100 allocations** (`frame_cost_test.go`, measured 100 again on `ce304b09`). Spec §5: **"The status-bar cache keys on inputs, never on time; the ~60 Hz pipeline stays untouched (the status bar is not on the progress path)."**

**The pattern to copy** is `TaskListModel`'s, verbatim in shape: a `renderCache string` + a comparable key struct, compared at the top of `View` and stored at the bottom. Two differences, both deliberate:

- **No `sec int64` field.** `taskListKey` and `jobDetailsKey` carry the wall-clock second because their headers show countdowns and timestamps. The status bar has no clock and no update badge — spec §5 says so explicitly — so a cached bar can never go stale on its own, and adding a second field would throw away 59 of every 60 cache hits for nothing.
- **No `invalidate()` and no setter changes.** `ShowChordHint` and `SelectedCount` are PUBLIC fields written directly from `app_layout.go` on every frame, and `offline` / `sidecarDown` are package-internal fields written directly from `app_update.go` and `app.go`. None of them has a setter to invalidate from. Putting them in the key is not a workaround, it is the simpler design: an input that is in the key re-renders naturally when it moves, and no writer anywhere can forget to call anything. Every setter (`SetWidth`, `SetCookieStatus`, `SetActivePlatforms`, `SetJobs`, `SetDiskStatus`, `SetBackfillStatus`) is covered the same way.

`SetJobs` additionally computes the tally once and stores it, so the key can hold the three derived numbers rather than an unhashable slice — and so a cache miss no longer walks the job list at all. (`metricTiers` calls `tallyJobs()` **once** per frame today, not once per tier: the "about eight walks" figure in `barJobCounts`' existing comment describes a state that was already fixed.
