# TUI Audit — Full Review Catalog (2026-03-10)

21 files, ~13K lines audited. Findings organized by severity, then by file.
After deduplication and verification: **~80 actionable issues**.

---

## Critical (1)

### C1. settings.go:629-633 — `hasRestartChanges()` always returns false
**Category:** Bug
`handleClose()` copies `values` into `originalValues` on lines 629-632, then calls `hasRestartChanges()` on line 633, which compares the two — but they were just made equal. The restart overlay (`showRestartOverlay`) is never shown, regardless of what was changed.
**Fix:** Call `hasRestartChanges()` before updating `originalValues`, store the result, then use it after the copy.

## Important Bugs (14)

### I1. app.go:1939 — `importDlg.SetSize` missing from `recalcLayout()`
Every overlay dialog has `SetSize` called in `recalcLayout` except `importDlg`. Resizing the terminal while the import dialog is open leaves it with stale dimensions.
**Fix:** Add `a.importDlg.SetSize(a.width, a.height)` alongside the others.

### I2. app.go:1482 — `updateSelectedJob()` missing after job deletion
After "A D" delete, `MoveUp()` is called but `updateSelectedJob()` is not. The details panel shows the deleted job until the next async `JobsUpdateMsg` arrives.
**Fix:** Add `a.updateSelectedJob()` after `a.taskList.MoveUp()`.

### I3. app.go:1119 — Async closure captures `a.setupWiz.OnFinishAutoCookie` through `a`
The `finish_cookie` handler accesses `a.setupWiz.OnFinishAutoCookie` inside a `tea.Cmd` closure that runs on a background goroutine. Other handlers correctly capture callbacks to local variables first.
**Fix:** Capture `finishFn := a.setupWiz.OnFinishAutoCookie` before the closure.

### I4. settings.go:536 — Backtick key double-dispatches in Network text fields
When editing a text field in the Network section, pressing backtick both: (1) gets typed into the text input via `UpdateComponents` (which runs first), and (2) triggers security mode via `HandleKey`. The key is processed twice.
**Fix:** Skip the backtick/tilde intercept when the current field is text/number type and the text input is focused.

### I5. settings.go:363-367,444-445 — DECAPI interval nil→0→pointer lossy round-trip
Loading: `nil` (meaning "dynamic") becomes `"0"`. Saving: `"0"` becomes `&0` (non-nil pointer). The nil semantics are lost. Relies on downstream config validation to re-nil invalid values.
**Fix:** Use empty string `""` for nil. Only set pointer when non-empty and in valid range (15-3600).

### I6. settings.go:879-898 — `valuesToChannel` drops explicit `Enabled=true`
When the channel value is "Yes", `Enabled` stays `nil`. While `IsEnabled()` treats nil as true, editing and saving a channel strips the explicit `Enabled: true` from TOML output (nil with omitempty = omitted).
**Fix:** Set `Enabled = &true` when value is "Yes".

### I7. action_menu.go:565-567 — Header line overflows content width by 8 characters
"Action Menu" (11) + gap + "↑↓ navigate | Enter | Esc" (25) = 36 chars minimum. The magic constant is `28` (should be `36`), so the header is always 8 chars wider than contentW.
**Fix:** Change `contentW-28` to `contentW-36`.

### I8. add_video.go:445,456,477,493 — Missing `syncToTextInput()` on Timestamps step transition
Moving from AudioFormat to Timestamps doesn't call `syncToTextInput()`. The text input stays blurred, so the user can't type into start/end time fields until they press Tab.
**Fix:** Call `m.syncToTextInput()` after every `m.step = AddStepTimestamps` in `handleFormatStep`.

### I9. add_video.go:438-458 — 'a'/'n' keys advance format step during loading
Pressing 'a' (Auto) or 'n' (None) while formats are being fetched advances to AudioFormat, but `m.formats` is nil. The audio table is uninitialized — blank step with no way to select.
**Fix:** Return early at the top of `handleFormatStep` if `m.loading`.

### I10. trim_dialog.go:229-232 — Text input not re-focused on Esc from step 1→0
Escaping from the confirmation step back to input step doesn't call `m.textInput.Focus()`. The text input never receives updates and typing is impossible.
**Fix:** Add `m.textInput.Focus()` when transitioning back to step 0.

### I11. trim_dialog.go:240-243 — Text input not re-focused on Esc from Delete→Create
Same issue: escaping from TrimModeDelete back to TrimModeCreate doesn't focus the text input.
**Fix:** Add `m.textInput.Focus()` after setting `m.mode = TrimModeCreate`.

### I12. import_dialog.go:206-207 — No minimum box size clamp
Unlike every other dialog, `boxW` and `boxH` have no lower-bound clamp. Very small terminals produce negative widths passed to `lipgloss.Style.Width()`.
**Fix:** Add `if boxW < 40 { boxW = 40 }; if boxH < 10 { boxH = 10 }`.

### I13. import_dialog.go:70,88 — Filepicker height can go negative
`m.picker.SetHeight(m.height - 8)` with no clamp. Terminal height < 9 produces negative picker height.
**Fix:** `pickerH := max(1, h-8)`.

### I14. help.go:197 — Header spacing uses wrong magic constant
The constant `20` doesn't account for actual left-side width (4-11 chars) or right-side hint (25 chars). The header overflows at narrow widths.
**Fix:** Compute padding dynamically from actual measured widths.

## Minor Bugs (22)

### M1. app.go:2154 — HTTP 409 "Job already exists" rendered in green (success color)
The feedback message doesn't match any warning/error patterns in `feedbackColor`. A 409 should be yellow/warning.
**Fix:** Change message to match a warning pattern, or check `IsError` field.

### M2. app.go:1567-1571 — "O S" with empty stream URL gives no feedback
When `streamURL(job)` returns empty, nothing happens. Other actions provide feedback for both success and failure.
**Fix:** Add `a.setFeedback("No stream URL available")`.

### M3. app.go:1676 — `streamURL` returns `"https://www.twitch.tv/"` for empty ChannelName
A valid but useless URL. `canOpenStream` won't detect the absence.
**Fix:** Return `""` when `j.ChannelName == ""`.

### M4. app.go:431-485 — `listenForUpdates` goroutine blocks forever when all channels nil
If all update channels are nil or closed, the `select` blocks indefinitely. Minor goroutine leak.
**Fix:** If all channels are nil, return nil instead of spawning a blocking goroutine.

### M5. app.go:84 — `IsError` field on `addVideoResultMsg` is never read
Set at lines 2149/2163 but ignored by the handler. `feedbackColor` uses string matching instead.
**Fix:** Either use it in feedbackColor or remove the field.

### M6. settings.go:516-520 — Error status cleared on any keypress including navigation
Pressing arrow keys to navigate away from an error field instantly dismisses the validation error message.
**Fix:** Only clear error status on keys that represent edits, not pure navigation.

### M7. settings.go:368-372 — Twitch interval nil→15→pointer lossy round-trip
Same pattern as I5 but less severe since 15 is the actual default. Still mutates config on no-op save.

### M8. settings.go:1461 — Network section uses `h-12` magic number for field height
Undocumented magic number tightly coupled to the security section's actual height.
**Fix:** Compute dynamically or add a comment.

### M9. settings.go:1528 — Section header not truncated to available width
With all 10 section names, the header can overflow on narrow terminals.

### M10. settings.go:1752-1754 — Channel list pagination counts action bar in maxH
One fewer channel is visible than intended because the action bar line is counted against the max.

### M11. settings.go:335-338 — SetSize doesn't re-scroll or clamp fieldIndex
After terminal resize, scrollOffset could be stale, causing the selected field to be off-screen.
**Fix:** Call `ensureFieldVisible()` from `SetSize()`.

### M12. settings.go:362 — FeedCheckInterval loses fractional minutes on round-trip
`int(cfg.Monitors.FeedCheckInterval.Minutes())` truncates. A value of `10.5` silently becomes `"10"`.

### M13. ffmpeg_check.go:114-125 — Review viewport height never updated on resize
Height was set to 6 in `ShowReview` and never changes. Terminal resize while in review mode keeps viewport at 6.
**Fix:** Update `reviewViewport.Height` in `SetSize` when in review mode.

### M14. ffmpeg_check.go:87-101 — Open() doesn't reset all state
`reviewScript`, `reviewToken`, `manualPath`, etc. are not reset. Stale state from a previous session could leak.

### M15. ffmpeg_check.go:141-145 — Review mode routes all messages to viewport including keys
Up/down keys are processed by both the viewport (scroll) AND handleReviewKey. Works by coincidence since handleReviewKey ignores up/down, but fragile.

### M16. add_video.go:381 — Missing text input blur on Esc from Timestamps to AudioFormat
The text input remains focused, consuming keystrokes that should reach the audio format table.
**Fix:** Add `m.textInput.Blur()`.

### M17. add_video.go:1100-1136 — `parseTimeToSeconds` accepts out-of-range segments
`"99:99:99"` parses successfully to 362439 seconds. No range validation on minutes/seconds (0-59).

### M18. action_menu.go:486-516 — Mouse click uses stale geometry in confirm mode
`overlayGeometry()` computes based on `contentHeight()`, but confirm mode uses a fixed `ch = 3`. Mouse coordinates are wrong for the confirm box.

### M19. trim_dialog.go:366 — No bounds check on `selectedTrimIdx` before accessing trims
If `SetTrims` is called with a shorter list while in delete mode, `selectedTrimIdx` could be out of bounds.

### M20. job_details.go:93-102 — Empty title shows blank instead of falling back to VideoID
The task list correctly falls back to VideoID when title is empty, but the details panel's Title row shows empty.
**Fix:** Use `title := j.Title; if title == "" { title = j.VideoID }`.

### M21. log_viewer.go:214-231 — `extractLogLevel` uses substring matching (false positives)
`strings.Contains(upper, " ERROR ")` matches anywhere in the message body, not just the level field. A log like `"INFO Cleared ERROR state"` would be classified as ERROR.
**Fix:** Use positional parsing.

### M22. client_tokens_dialog.go:68,79 / files_dialog.go:81,92 — Inner DimStyle prevents outer highlight color
Nested ANSI styling: inner `DimStyle.Render()` parts don't adopt the outer selection/confirm highlight color (yellow/cyan). Selected items have inconsistent coloring.
