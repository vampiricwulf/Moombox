## Features

- **Recover the recordings a mid-stream restart set aside.** When the engine has to restart a stream it keeps the partial recording aside instead of discarding it; those recordings are now listed under the job in both UIs and a Recover action muxes each one into its own file beside the archive, carrying a kept chat capture beside the first. Use the Recover button in the job dialog, the `A S` chord in the TUI, or `POST /api/jobs/{id}/recover-asides`; Recover and `/mux` share one per-job claim, so either answers 409 while the other is running.
- **The resolution cap now measures the shorter edge of the frame.** `downloader.max_video_resolution` compares against the shorter dimension, so 2160 means 4K whether the source is landscape or portrait, and Moombox picks the largest rendition at or below the cap, else the closest one above. **The shipped default of 2160 therefore admits 3840×2160 on YouTube where the old rule effectively capped it at 1920×1080 — every install that kept the default will download 4K where it used to download 1080p.** Both UIs and both setup wizards now offer the setting as a list — Unbounded first, then 480p through 8K, plus Custom — over the same integer key, so a hand-written value still round-trips; set it lower, or to `0` for unbounded, if 4K is not what you want.
- **Twitch enhanced broadcasts (HEVC and AV1) are captured.** Moombox now asks Twitch for its enhanced renditions on every playlist request and parses their codecs; there is no setting — an enhanced broadcast is always taken. At the chosen size it ranks AV1 above HEVC above H.264, then source over transcode, then bandwidth; playlist order is the last tiebreak. HEVC needs hardware decoding in Chrome and Edge and does not play in Firefox; it is chosen only when AV1 is absent.
- **Configurable reorder-buffer ceilings for VOD downloads.** `downloader.reorder_buffer_mb` caps one job and `downloader.reorder_budget_mb` caps the whole process; `0` means unbounded and both are editable in the Web and TUI settings. On x64 the per-job ceiling rises from a fixed 256 MB to 1 GB under a new 4 GB process cap; arm64 keeps 256 MB per job and 1 GB overall. A save moves the process total immediately, but a download already running keeps the per-job ceiling it started with.
- **The TUI renders at 120 fps.** The terminal renderer runs at 120 frames per second (was 60) and the fast progress tick is 8 ms while a download is delivering; the idle tick and the one-second clock are unchanged. A no-change frame still costs the same 30 allocations, and the extra tick measures at roughly 2–4% of one CPU core during a download.
- **`downloader.progress_interval_ms` sets the engine's progress-report rate.** Integer milliseconds, default 16, minimum 1, no maximum; a value below 1 falls back to the default with the usual config warning. It is a `config.toml` key with no Settings row in either UI. Lowering it costs disk: at 8 ms a job writes about 125 progress rows per second instead of 62, each one a full-sync SQLite commit, so roughly eight simultaneous downloads at 8 ms will saturate a typical disk where sixteen fit at 16 ms. A job started after a save picks up the new value without a restart; a download already running keeps its own.
- **Super Chats, Super Stickers and memberships are cards in the player's chat sidebar.** A Super Chat or Super Sticker renders as a two-part card in the colours the archive recorded (YouTube's seven-tier palette as the fallback for older files, gray for an unknown tier), with one text colour picked for contrast; a message-less Super Chat is header-only as on YouTube and a sticker's body reads "Super Sticker" because sticker images are not archived. Membership events — new members, milestones and gifts — are green member cards. The video overlay is unchanged.
- **Twitch subs, resubs, gifts, raids and cheers render as notices and chips.** A sub, resub, gift or raid is a purple-accented block with its system line above any message the viewer typed (built from the event's own fields when the wire carried none), and bits carry a cheer chip on Twitch's own amount scale: gray under 100, purple at 100, green at 1,000, blue at 5,000, red at 10,000. All of the new text is searchable from the sidebar filter.
- **Twitch `system`-typed notices render as notice blocks too.** Rituals, Prime upgrades, viewer milestones and bits-badge tiers now appear as dim notice blocks in the player sidebar with the system line first; an event whose system line is empty keeps the plain row it had before, and a notice whose archived message merely repeats its system line (Twitch sends the line as the message when the viewer typed nothing) no longer shows it twice.
- **Membership header text and gifted memberships are archived.** A YouTube membership event keeps its header line ("Welcome!", "Member for 6 months") in a new `membershipText` field, and gifted memberships — both the purchase and the redemption — are no longer dropped from the archive. Every existing chat file still loads unchanged.
- **A dead BotGuard sidecar is visible and self-healing.** The sidecar is supervised and restarted in place on a backoff ladder, and an outage now shows up instead of failing silently: the TUI status bar carries a red `SIDECAR DOWN` (`POT` when the bar is narrow), the dashboard raises a status alert, and `/api/status` reports `botguardSidecar`.
- **A chat capture that stopped short reads as `incomplete`, not finished.** `chat_status` is now derived from the chat downloader's outcome rather than the message count, with one new value for a Twitch VOD whose paging stalled (its resume sidecar is preserved, so it can be retried), a chat still running when its job finalizes, and a restart mux that kept a chat sidecar. The Web badge and the TUI details row both show it.
- **`cookies.dpapi_profile_dir` points the Windows DPAPI fallback at a relocated profile.** Name a portable Chromium, a `--user-data-dir` install or an Opera profile directory and the cookie read will use it; it needs `cookies.dpapi_fallback = true` and is a `config.toml` key with no UI setter.
- **TUI navigation and everyday conveniences.** PgUp/PgDn page the Tasks, Details and Logs panels and Home/End jump to the first and last task; Ctrl+C quits from inside every overlay; `O C` copies the stream URL through OSC 52 everywhere and additionally through `clip.exe` on a bare local Windows console; an action-menu entry with no matching job dims and says why instead of dead-ending; `A D` no longer offers Delete on active jobs; `R Y` gained a "Plugin state" row for a plugin file it cannot parse; the log panel hard-wraps at insertion, `/` finds matches on wrapped continuation rows, and the "Logs (N)" header counts source lines rather than wrapped rows; a TUI update dropped while the list was busy is replayed on the next successful send; `hide_finished_age_days` saved in the dashboard now reaches the TUI; and a local build from a dirty tree reports its commit with a `-dirty` suffix in `--version` and the startup log.
- **Dashboard: Open Folder works on Linux, and the status bar is keyboard-reachable.** Open Folder opens a real file-manager window on Linux (and answers with a clear message on a headless host) through the same helper the TUI's `O F` uses. The four clickable status-bar controls carry roles, tab stops and labels and respond to Enter and Space, and the last remaining browser alert is a toast.

## Improvements

- **Origins must now be attested by your certificate on `external` and `public` installs.** With `network_access = external` or `public`, a request's origin must both match the request's own host and name a host that the operator-installed TLS certificate attests (DNS and IP SANs; a `*.` SAN spans one label). Moombox's own self-signed placeholder never narrows anything, and `localhost`/`lan` widen only by literal SAN names. If you reach your dashboard by a name your real certificate does not cover, add it to the certificate or you will get `invalid origin`.
- **One origin decision behind CORS, CSRF and the WebSocket.** The upgrade now shares the same check, is port-exact like CSRF, reads `X-Forwarded-Host` only from an address listed in `trusted_proxies`, and fails closed if no check is wired; refusal log lines name the host that was compared. A reverse proxy must forward `Host` verbatim or be listed in `trusted_proxies`.
- **`/` and `/index.html` serve the cache-busted index.** The root now serves the same version-stamped page as the SPA fallback, with `no-cache` and a content ETag; an untrusted or dirty build gets no version stamp at all.
- **`-config` is authoritative and saves go back to the file that was loaded.** An explicit `-config <path>` is never fallen through to another file, a missing explicit path is created there, and the boot log names the file in use. `-log-level` is now a per-run override only — it is no longer written into `config.toml` by the boot auto-persist, the password auto-hash or any UI save.
- **Clearer recovery after a bad update.** A binary that fails its first boot after an update is kept as `<exe>.failed` until the next healthy boot, a deterministic startup failure exits with code 3 and is never mistaken for a failed update, and a second in-place update prefers a surviving `.old` as its rollback artifact. The database schema-downgrade refusal now names the real kept file (`<exe>.failed` / `<exe>.update-failed`) instead of a `.old` that does not exist.
- **Downloads resume instead of restarting, and never silently truncate.** Non-empty staged media is never truncated without an explicit discard, only unrecognisable staging is discarded, the direct-download fallback resumes, a `206` that starts at the wrong offset is rejected, and media is fsynced before each resume checkpoint. The segment timeout is now a read-progress deadline rather than a total one, under a 15-minute hard ceiling, so a slow-but-alive segment is no longer killed.
- **Restarts and shutdowns finish the work that is already on disk.** A job restarted while it was muxing muxes what is staged instead of re-downloading, a shutdown cancels and finalizes a mux rather than abandoning it, the muxed output is verified before the rename, and a VOD waits for its chat pager to finish after releasing its download slot so another download can start.
- **YouTube extraction tracks upstream more closely.** Every age-gate shape yt-dlp recognises is handled, the IP-block verdict fires the way upstream's does and names the substitute, DRM-only responses keep their real status and the DRM warning names the client, a player response for a different video is rejected, forged player-response candidates are skipped, and one preferred rendition per itag reaches every consumer.
- **Fewer YouTube requests per job.** The quality monitor probes with a single authenticated player call, a waiting room stops hunting for formats it cannot have, the watch page is reused for chat and parsed once, and a post-live chat capture runs as one bounded replay pass that records a give-up on the job row instead of spinning.
- **Twitch capture is steadier.** A broadcast is declared over only when two samples about five seconds apart agree; a client-initiated IRC keepalive detects a half-open socket in about 70 seconds without charging the reconnect budget; a routine server `RECONNECT` reconnects instead of ending chat capture; IRCv3 tag escapes are decoded; VOD chat pages by edge cursor and an abnormal page marks the archive stalled with its sidecar preserved rather than claiming completeness; emote lookups are cached only on an answer, expire after 24 hours and serve stale on a failed refetch; and a `429` asking for longer than Moombox will wait returns instead of retrying.
- **Channel monitoring is quieter and fairer.** A refused anonymous DECAPI probe is remembered instead of becoming a job, every `429` engages the limiter and a fallback window never shortens the server's own back-off, Twitch channel checks are staggered, notification targets dedupe by resolved webhook URL, disabling a channel pauses its backlog, and the cookie-repair sweep returns parked backlog VODs to `Queued` so they are re-admitted through the per-channel archive-slots pacing.
- **Cookie handling is safer and more responsive.** A cookie import that collides with an in-flight refresh pass is refused with 409 instead of being overwritten by it, a cookies.txt that cannot be read is shown as its own state ("cookies.txt could not be read") on both dashboards and keeps retrying, the import and finish endpoints answer in milliseconds instead of waiting out their re-check, the browser auto-setup endpoints and buttons are loopback-only (LAN viewers are told to use Import instead), a snap-packaged Chromium is refused at launch with a reason, the POSIX `0700` parent chmod applies only to a directory Moombox owns (never a mounted `/data`), and the DPAPI fallback exits quietly with one debug line off Windows.
- **The dashboard is lighter under load.** A progress tick is now a slim `job_progress` frame (313 bytes instead of 6.2 KB) merged onto the row the client already holds, the job card's progress cell and the details and stats panels only write to the DOM when a value actually changed, the log panel appends once per animation frame, `chat.json` is streamed rather than buffered, gzip writers are pooled and skip already-compressed bodies, WebSocket drops are counted and answered with one rate-limited full-state resync, and the socket has a 4 KiB read limit.
- **Web hardening and caching.** `script-src` no longer allows inline scripts (the boot theme and login scripts moved to their own files), static assets are only marked immutable when the build commit is trusted, the release-notes route takes a strict version pattern (it could previously be steered to another release's notes), the three GitHub-quota routes share one debouncer, an imported chat file's video ID is validated, and an oversized upstream page is now an error instead of a silently truncated parse.
- **The TUI stays cheap at high frame rates.** The task list, details, header and log panels memoise on their inputs, the status bar is memoised behind a comparable key (a no-change frame fell from 100 to 30 allocations, the bar itself to zero), terminal jobs no longer hold progress entries, and the filter fold no longer allocates.
- **Settings validation and restart prompts tell the truth.** `PUT /api/config` now enforces the same ranges the config loader does — `disk.disk_warn_percent` and `disk.disk_critical_percent` between 1 and 99, `cookies.refresh_interval` between 10 and 10080 minutes — `cookies.refresh_interval` is marked restart-required in both UIs, the TUI round-trips fractional durations, and a verified FFmpeg path from `POST /api/ffmpeg/check` is applied to the live muxers immediately.

## Bug Fixes

- **Twitch emotes were drawn at the wrong place in messages containing non-ASCII text.** Twitch's IRC emote offsets index Unicode code points, not UTF-16 units; they are now converted for the player and verified against 120 real wire ranges. New chat files are marked, and the player repairs unmarked legacy Twitch files at load, per part.
- **Every job's log lost its own closing lines.** "download complete" and "removed staging directory" / "preserving staging dir" were written after per-job log routing had already been torn down, so they never reached the job's log. Both finalize paths keep routing open through those lines.
- **The Set-aside Recordings section disappeared from an open job dialog.** The dashboard's job-update handler did not carry the set-aside list forward on a status change, so the section vanished on exactly the Downloading → Cancelled/Error transition that first makes Recover offerable, until the dialog was reopened.
- **A cancelled Twitch job could return before its chat writer finished.** The cancel and shutdown paths now wait up to 2 seconds for the chat writer (with a warning if it overruns), which also removes an intermittent test failure caused by the same race.
- **Open Folder failed on Windows paths containing `=`.** Both the dashboard route and the TUI's `O F` now force-quote the path, and a bare drive root such as `D:\` opens again.
- **A cleanly ended HLS stream logged a spurious error and left a resume file behind.** Two of the three playlist-failure paths did not consult the stream-end verdict the way the third did; all three now finalize identically on a confirmed end, with no error line and no orphaned `.resume.json`.
- **Deleting one job cleared every job's log buffer.** The cleanup pruned by exclusion and wiped everything on a read error; it now clears exactly the one buffer.
- **Chat files, resume sidecars and description files are written atomically.** All three go through the shared atomic writer — a unique temp, fsync, and a rename that retries the transient "access is denied" an antivirus scanner can cause — so a crash or a scanner can no longer leave a half-written file. On Linux the file mode is now exactly `0644`.
- **A yt-dlp plugin file that does not parse is reported instead of ignored.** Both the dashboard card and the TUI's `R Y` overlay say it is unrecognised and offer a reinstall, and the plugin's bug-report link points at the Moombox repository.
