## Features

- **A YouTube discovery sends one "Stream Found", once Moombox knows what it found.** A newly found upcoming stream used to send "Stream Found" at creation and "YouTube Start Time Confirmed" seconds later, when the first metadata fetch filled in its schedule. The two are now one embed, sent after that fetch, whose description says what the video is (Upcoming, Upcoming premiere, Live, Premiering, Ended stream or Video) and whose fields carry Starts At with a live Discord countdown, Length, Ended or Published, Access (members-only, age-restricted, …) and a description excerpt. The announcement is owed by the job row itself, so a restart before the fetch still sends it, a duplicate detection never sends it twice, and a cancel or retry never announces a discovery long past. "Start Time Confirmed" still fires for a schedule that appears later; a target filtered to `scheduled` but not `found` receives it in place of the merged embed, and a target that pings on `scheduled` is pinged by the merged one. An upcoming stream with no schedule no longer shows its upload date as its start, and is probed every 30 seconds since it can go live at any moment.

## Improvements

- **Update actions act only on the release you were shown.** Update Now and Skip, on the dashboard and in the TUI, name the release whose notes are open: if another release became pending meanwhile, nothing is installed or skipped and the newer release's notes are shown instead. A TUI skip now clears every open dashboard's update badge and closes a dialog still offering that release, and an up-to-date answer from a manual check no longer hides a release another check found during the round trip. On Windows, a release that crashes late enough to escape the boot's milestone is still rolled back, and is now marked skipped and no longer announced as "Update Applied".
- **One password rule everywhere.** 8 to 128 bytes wherever a password is set — both wizards, Settings and the TUI's Security page — so a long passphrase can no longer be saved and then refused at login. No surface trims a password any more; one saved by an earlier wizard with a leading or trailing space still logs in, and every password field warns about outer spaces.
- **Archive imports record a single-file recording's length**, as split parts already were, and an import with no video id of its own no longer shows a broken thumbnail.

## Bug Fixes

- **First-run setup.** The browser login on the wizard's cookie step is carried into the cookie file the setup saves — and only the cookies this run's login or import supplied, so an earlier install's session is left behind. A setup whose output or staging directory cannot be created is refused instead of answered "success". Setup completes once, whichever wizard saves: two overlapping dashboard tabs, or the TUI wizard and the dashboard tab opened on boot, no longer overwrite each other's config and restart twice. A blank port keeps the wizard on the port it is served from, a refused Finish no longer leaves a stale redirect for the next attempt, and Settings' own restart redirect keeps the serving port when the port is unchanged.
- **TUI Settings.** A save writes only what the overlay changed, so edits the dashboard made meanwhile — notification targets included — survive it. A typed restart-required value prompts for the restart even when the dashboard saved the same value first. Two target edits the notification form used to hide (an event filter widened to every event, a URL with a stray space) are saved. The browser-path check runs with no config lock held, so a browser on a slow network share can no longer stall the whole process during a save.
- **Dashboard and TUI.** A cancelled import upload's late progress event no longer overwrites the running upload's bar, and the TUI's log viewer no longer leaves a blank row at the bottom when the auto-scroll hint goes away.
- **Server.** A panic in the cross-scheme redirect server is logged and answered with a 500 instead of dropping the connection. A backfill scan releases its context when it ends (a slow leak, one per channel per rescan). An archive import holds no JSON token past 1 MiB, so a zip whose metadata carries a huge string cannot exhaust memory. `Defaults()` no longer shares its connectivity probe targets with the loaded config, so a `config.toml` listing fewer targets no longer rewrites the shipped defaults for the rest of the process.

## Internal

- Spec: the archive import's zip-bomb and JSON token limits are documented, appendix-metrics is regenerated, and `CanonicalPath` and the path guards say a Windows junction is kept as spelled.
- Tests pin the periodic update check's gates, the launcher's and TUI's update wiring, and three edges of the deferred Stream Found; its seams are tidied behind one Discord timestamp renderer.
