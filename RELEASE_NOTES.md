## Improvements

- **Web UI mobile pass.** Reworked at the ≤ 768px breakpoint after "nearly everything too big" feedback. Tasks/Archived rows are now compact horizontal cards (small thumb on the left, title/status/progress stacked next to it, single overflow dropdown for actions). Settings sidebar is a horizontal-scroll chip strip. Job Details labels stack above values (was a 6rem column eating screen) and the up-to-9 action footer scrolls horizontally instead of vertical-stacking. Logs panel reverted from the bumped-up font-size-medium to dense x-small text, header reorganised. Files rows became compact flex cards. The prior 44×44px touch-target floor (which was the main cause of the "too big" feel) is now 40px for text buttons and 32px for icon buttons. Touch-device hover state suppressed so the styles don't get stuck on the last-tapped row.

## Bug Fixes

- **Deleting an active job from the TUI no longer leaves a stale "Cancelled" row in the Web UI.** The per-job 100ms leading/trailing-edge throttle on `BroadcastJobUpdate` raced against the unthrottled `BroadcastJobDeleted`: when the TUI cancels-then-deletes, the trailing-edge `job_update` with `status=Cancelled` arrived after `job_deleted` and the client's upsert handler re-added the row. Removed the hub throttle entirely — `ProgressTracker.maybeUpdate`'s 16ms gate already caps progress writes upstream at ~60Hz/job, and the other broadcast callers are event-driven.
- **Web UI auto-moves Finished jobs to Archived as they age, without a page refresh.** The TUI reclassified the whole list on every event (`isJobArchived`); the Web UI had no equivalent and left aged jobs in Tasks until reload. The server now ships `hideFinishedAgeDays` in `initial_state` and broadcasts a `config_update` event when the threshold changes (sent *before* the accompanying `jobs_update` so the client always has the fresh threshold when the data arrives). The client mirrors the TUI on every `job_update`, on `config_update`, and on a 60-second idle sweep.
