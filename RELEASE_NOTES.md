### Internal

- **Release pipeline rewritten as a single ubuntu-latest job.** All three binaries (Windows, Linux x64, Linux arm64) are now cross-compiled in parallel from one Linux runner via go-winres + `GOOS` env var, then signed in parallel. Embed blobs (sidecar tarball + Node binaries) are cached across runs keyed by `version.txt` + sidecar manifest + fetch-node source — most releases skip the ~55s of npm ci + nodejs.org fetch entirely. Estimated wall-clock dropped from ~2:47 to ~1:20 on cache-hit releases (~52% faster). All-or-nothing release semantics: any build/sign failure fails the whole release, no partial uploads.
- **Fixed a latent signing bug** that would have silently published releases with broken `.sig` files. The parallel sign step used a bare `wait` which returns 0 regardless of background process exit codes — any signing failure was swallowed. Now waits per-PID so failures propagate. The auto-updater's strict signature verification would have rejected those broken sigs on user machines, so this fix matters even though it never visibly broke a release.
