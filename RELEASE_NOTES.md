## Bug Fixes

- **Stale player JS cache no longer floods sig-decryption warnings.** When YouTube rotated a player JS (`8fb635c2` was the trigger — 2.5MB → 2.75MB / 12% growth in ~36 hours) the 14-day disk cache happily kept serving the old script to the sidecar's ejs preprocessor, which surfaced as `cipher: sig unavailable for this player` warnings and crippled signature decryption until manual cache eviction. Field instance: 56 warnings in 5 seconds when adding `bp4_7T9J6Fg`. Fixed via three coordinated changes:
  1. **Conditional-GET revalidation** in `internal/cipher/player_cache.go`. Each `Fetch` now sends `If-Modified-Since` / `If-None-Match` replayed from a persisted `<key>.meta.json` sidecar (capturing YouTube's own `Last-Modified` / `ETag` / `Content-Length` from the prior 200). 304 → return cached + refresh trio mtimes; 200 with rotated body → wipe `<key>.preprocessed.js`, evict in-memory compiled solver, return new content. Singleflight-coalesced on `CacheKey(playerURL)` so concurrent stream-setups share one round-trip even across locale URL variants. Disk TTL dropped from 14 days to 24 hours (offline backstop only — conditional-GET handles the steady state). Network-failure during revalidation falls back to cached rather than crashing stream-setup.
  2. **Reactive sidecar invalidation** when ejs returns the canonical stale-JS errors (`ejs solve sig: no solutions`, `ejs solve n: no solutions`, `ejs preprocess`). The sidecar solver now matches these patterns, calls `PlayerSource.RemovePlayerJS` to wipe disk + preprocessed + meta + in-memory + STS caches end-to-end, then retries the JSON-RPC with `ForceReload: true` AND fresh JS attached. Required a sidecar protocol change in `bgutil-sidecar/src/cipher.js` — the existing `if (!entry)` semantics silently ignored fresh playerJS for an already-cached playerID, so a naive retry couldn't have worked. Now `forceReload && playerCache.has(playerID)` evicts the entry before the load path. Persistent stale-JS surfaces as a new `cipher.ErrPlayerJSStale` sentinel.
  3. **Deferred per-format cipher decryption.** `parseFormatsWithCipher` (which decrypted sig + n on every adaptiveFormat URL during player-response parsing — 7-26 calls per stream setup) is replaced by `parseFormats`, which captures the raw URL + `EncryptedSig` / `SigKey` from sigCipher entries without invoking any solver. Worker strategies (manifestless DASH, VOD) now resolve the chosen format(s) post-selection via the new `cipher.ResolveFormatURL`, with bounded re-selection on failure. ~10× reduction in cipher calls per stream lifetime, and shrinks the surface area where stale-JS can surface.

  Migration is automatic — pre-existing cached files without `<key>.meta.json` fall back to file mtime as `If-Modified-Since` for the first revalidation and capture real metadata on the next 200.

## Internal

- New `tools/sidecar-sig-probe` diagnostic now accepts `-player-js PATH` to replay a stale cached player JS through an isolated sidecar instance, reproducing the exact field failure end-to-end. Supersedes the one-shot `tools/manifestless-dash-probe` (removed — its purpose was validating the v2.6.23 manifest-free DASH path, which is now production-tested).
- New `cipher.PlayerSource.RemovePlayerJS` interface method; `*GojaResolver` provides the implementation by reusing `InvalidateSolver`.
- New `cipher.ErrPlayerJSStale` sentinel for callers that need to distinguish "extractor literally can't handle this player" from generic cipher errors.
- Plan document committed to `docs/plans/cipher-pipeline-rework.md` as the design contract for this work.
