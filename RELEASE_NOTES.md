## Features

- **Restart Moombox from the web UI.** A new **System** settings section adds a "Restart Moombox" button (with a confirmation dialog). `POST /api/restart` is no longer loopback-only — it now relies on the standard access stack (IP gating by `network_access` + CSRF + session auth), so any connection you allow — local, LAN, or authenticated external — can restart the app. Unlike applying an update (which stays loopback-only because it swaps the binary), restart only relaunches the same binary, so in-progress downloads are saved on shutdown and resume on startup.

## Bug Fixes

- **Recover from offline mode when the network returns.** The connectivity monitor could stay offline indefinitely after an outage. Once offline, every subsystem stops making network requests, so nothing cleared the passive failure latch — and the poll loop read that latch without pruning, pinning the monitor offline forever even after connectivity came back. The poll loop now prunes the aged-out latch each cycle and recovers as soon as the active probe sees the network again. Also fixes a related latch-clear gap that only checked the failure-count threshold and ignored the distinct-subsystem threshold.
- **Reject out-of-range `hide_finished_age_days` with 400, not 500.** The `PUT /api/config` validator only checked the lower bound, so a value above 365 passed validation and then failed later in config save with an opaque 500. The canonical `0..365` range is now enforced in the handler (matching every other monitor field), returning a clean 400 with a per-field detail.
- **Archive-classification parity, broadcast races, and Tasks/Archived dedup.** The WebSocket archive filter now matches the REST filter exactly (float-precision `0..365` with a `<0` never-archive guard), so the dashboard and API classify every job identically; the `hide_finished_age_days` threshold is captured once so the `config_update` value can never disagree with the threshold a `jobs_update` was filtered at. Client-side, a job is pruned from the archived list when it re-enters the active list, and `job_deleted` / `job_update` no longer leave a stale or duplicated row across the Tasks and Archived panels.
