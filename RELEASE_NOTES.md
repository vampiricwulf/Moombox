## Features

- **Twitch: gap-proof multi-part recording.** Twitch live has no DVR — segments that slide out of the playlist window are gone forever. When that happens mid-recording, Moombox now closes the current file as a complete, internally-gapless part and continues in a new one, instead of splicing a jump into a single file. Parts are named `{name} - part1.mp4`, `part2`, …, each with its own synchronized chat file, and are listed on the job in both the Web UI and the TUI's new **Parts** section. A job that ends with exactly one part keeps the plain filename. Quality changes and connectivity outages ride the same machinery, and parts whose mux was interrupted (crash, restart) are recovered at finalize.
- **Live "what is it waiting on" indicator.** When a download isn't actively pulling segments, the progress line now says why — "Waiting for next segment… (12s)", "Verifying stream ended…", "Connection lost - reconnecting…", "Rate-limited - backing off…" — with a live elapsed counter, instead of freezing on the last segment count. Shown on Web UI job cards, in the TUI details panel, and as a dim "⋯ wait" tag on TUI task rows.
- **Twitch stitched-ad skipping.** Server-side ad segments (detected via Twitch's ad markers in the playlist) are skipped without being written, so recordings no longer contain the spliced ad media — one log line per break instead of one per segment.
- **ffmpeg-style HLS live pacing.** The HLS live loop reloads the playlist on ffmpeg's cadence (the last segment's duration while flowing, half the target duration when stalled), so recordings hug the live edge instead of drifting behind and catching up in bursts.
- **Crash supervision and self-update rollback safety.** The launcher now restarts Moombox after an abnormal exit (exponential backoff, crash-loop cutoff) and sends a "Recovered From Crash" notification. If the first boot after a self-update fails, the previous binary is preserved with written recovery instructions instead of being deleted at exactly the wrong moment; "Update Applied" / "Previous Update Failed" notifications close the loop, and the update dialog's dismiss button now skips just that version instead of disabling update checks entirely.
- **Notifications: more events, reliable delivery, hot-reload.** New events for gap splits, connectivity lost/restored, disk critical, update applied/failed, crash recovery, and unhealthy channels. Discord delivery retries transient failures and honors rate-limit waits instead of dropping the embed. Webhook URLs are validated at save time and can be test-sent from both UIs, and notification edits apply immediately — no restart.
- **Channel health monitoring + force check.** A channel that fails monitor checks for a sustained streak (renamed, banned, deleted, misconfigured) now surfaces in `/api/status` and triggers a "Channel Not Responding" notification — cross-confirmed between the RSS and DECAPI monitors so a single-source outage doesn't false-alarm. Click the header countdown (Web) or press `R M` (TUI) to force an immediate poll of all monitors.
- **Faster stream detection.** Twitch channels are checked in one batched GQL request per 30 channels instead of one round-trip each; monitor intervals are now true fixed-rate periods (cycle time no longer silently inflates the cadence); unscheduled YouTube uploads poll at the 5-minute band instead of 10; imminent scheduled streams poll every 30s.
- **YouTube: yt-dlp-matching format selection.** Video codec preference is now AV1 > VP9 > H.265 > H.264 > VP8 with higher bitrate winning ties — matching yt-dlp's defaults, including Premium enhanced-bitrate formats when the account is entitled to them.
- **YouTube: configurable maximum timeout.** New downloader setting `maximum_timeout` (default 600s, min 30): how long a stalled YouTube livestream keeps retrying — re-checking every 30s whether it actually ended — before finalizing even if YouTube still reports it live. Replaces the old `segment_retry_delay_cap` / `segment_live_check_retries` knobs.
- **Post-live VODs download reliably.** Just-ended streams that YouTube serves as segment-only formats now use the manifest-free DASH path; whole-file formats are routed to direct download and never into the segment loop; parts that start mid-stream fetch their ftyp+moov init from segment 0; and finished direct downloads are validated (WebM accepted, error pages and bare fragments rejected loudly) instead of producing an unplayable file.
- **TUI: fuzzy task search.** Press `/` in the Tasks panel to live-filter jobs by title, channel, or video ID; `Esc` clears.
- **Configurable probe cooldown.** `monitors.probe_cooldown` (seconds, default 0 = disabled) rate-limits re-probing the same video's metadata; the feed and DECAPI monitors keep independent cooldowns so one can't blind the other.

## Improvements

- **Web UI performance on 24/7 dashboards.** The 1 Hz refresh is scoped to the visible panel and pauses while the tab is hidden; huge VOD chat sidebars build in chunks (no more multi-second freeze on 50k+ message chats); hidden Archived-panel renders are deferred; the details dialog reliably shows Resume/Mux buttons.
- **TUI performance.** The marquee, log-flush, and progress tick loops are demand-driven — they run only while something needs animating, flushing, or counting — while progress stays real-time (60 fps during active downloads) and new log lines still render immediately.
- **Session fingerprint hygiene.** The desktop Chrome User-Agent is randomized per start within yt-dlp's current version window (it had been frozen at Chrome 131 for months), and the iOS/Android app client versions were refreshed — all sourced from one constants catalog with tests that fail when they rot.
- **Linux parity hardening.** Browser, sidecar, and supervised child processes die with Moombox via PR_SET_PDEATHSIG; permission tightening uses chmod 0700/0600; disk monitoring survives a not-yet-created output directory; browser/folder opening uses xdg-open.
- **HTTP/HTTPS cross-scheme redirect.** Visiting the wrong scheme on the configured port now 307-redirects to the right one (both directions, when a certificate is available) instead of a raw protocol error.
- **Database correctness.** SQLite pragmas are now actually applied — the old DSN form was silently ignored, leaving WAL, the 5s busy timeout, and foreign-key enforcement off; orphaned child rows accumulated in that window are swept. A downgrade guard refuses to run an older binary against a newer database schema, and `moombox add` refuses to touch a mismatched-schema database instead of migrating it out from under the daemon.
- **Write-path durability.** Resume sidecars, chat files, cookies, and config all fsync before rename; chat appends write-then-truncate so a crash can never leave invalid JSON; the cookie merge prunes expired rows; cookie writers use unique temp files so concurrent writers can't interleave.
- **Memory bounds.** Far-behind catch-up batches are capped (protects low-RAM arm64 hosts), playlist parsing rejects oversized bodies, the sidecar's interpreter-VM leak on BotGuard rotation is plugged, its network fetches are time-bounded, and memory-limit settings are validated.

## Bug Fixes

- **Project-wide review fixes.** Two full review passes over this release's range produced ~150+ verified fixes across every package — download engine (direct-resume streaming-fallback corruption, Windows O_APPEND truncate failures, mid-download 200-splice, resume identity across manifest refreshes and tilded manifest IDs), worker orchestration (restart/resume seeding integrity, outage edge cases), web, TUI, cookies, and cipher.
- **Whole-file formats can no longer trigger a disk-filling loop.** A format carrying a contentLength is a complete file; feeding its URL to the `&sq=N` segment loop re-downloaded the entire file for every sequence number, forever. Both the strategy gate and stream selection now exclude them.
- **Restart-resumed recordings keep honest metadata.** Parts that survived a daemon restart derive their true start time from the muxed duration instead of being stamped with the restart time, and a restarted job never appends into a part that was already muxed.
- **Chat archives are safer.** Chat resume state survives interruptions (a restart previously rewrote hours of archived chat from scratch), boundary batches that fail to write at a part roll are spilled to a recovery file, and emote enrichment writes atomically with fsync.
- **TUI details-panel title now scrolls smoothly** instead of jumping several characters at a time, and skips redundant redraws during its end-of-line pauses.
- **UI polish.** Notification-editor clicks map correctly when scrolled; task search closes on focus loss; thumbnails retry once when the local file appears server-side; imports accept CJK/emoji titles; the login error message displays again; search filters handle quoted phrases and mid-word apostrophes; `status:`/`platform:` filters are case-insensitive; a stale "update available" badge clears once the update lands; the SPA reloads itself after the server updates beneath it (deferring if you have unsaved settings).
- **Final-review hardening.** The pre-release pass over all of the above: HLS VOD gap bookkeeping is exact under cancellation and worker panics, the playlist-error counter resets on successful fetches, Twitch IRC writes are interruptible on stop, ad-break tallies survive mid-break exits, and n-param decryption failures now log a warning instead of silently degrading to throttled downloads.
